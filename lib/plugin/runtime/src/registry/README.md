# 持久 Component 激活

`PersistentComponentSlot::open(ComponentDatabase::releases(), ...)` 创建绑定来源 UUID 和租户的 v2 执行槽。执行槽只消费 `ComponentReleases` 与 `ReleaseLease`。默认 `PostgresReleases` 把整包、实际能力、活动版本及变更历史保存在原宿主 PostgreSQL schema；插件数据角色不可访问。宿主先通过 `install` 绑定数据库并完成受控增量迁移，再提供 `InvocationResources` 激活。

`activate` 在旧版本继续服务时完成候选校验与生命周期，随后排空本进程请求，并通过后端的版本读租约排空其他宿主中的在途请求（PostgreSQL 实现使用行锁）。活动记录提交后才交换本地实例。并发发布使用代数比较，失败保留已有版本。取消期间提交结果不确定时，旧实例拒绝后续调用，由 `restore` 恢复数据库中的版本。

启动时使用 `stored` 读取锁定整包及能力，再绑定对应资源并 `restore`；恢复仍须使用宿主当前允许的能力。旧摘要不能访问新版本。`deactivate` 持久撤销，`unload` 仅卸载本进程。迁移允许追加已校验的非破坏性建表/索引；不能用删除历史迁移进行回退。

这是 v2 运行库能力。正式产品的身份、导航、挂载票据和发布授权必须由产品接入，不把旧协议的发布接口作为适配器。

失败请求在申请更新锁之前释放后端读租约，避免与并发发布互等；失效操作只移除发生失败的实例，不清除已经提交的新版本。恢复必须先成功结束后端读取，再切换本地指针。
