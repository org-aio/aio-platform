# Studio 源码职责目录

Studio 的源码按功能边界组织；`lib.rs` 只声明模块、导出公共能力并编排顶层入口。

- `business/`：应用编译、业务模块生成、约定接口和服务骨架。
- `compiler/`：程序编译、分阶段校验、页面/函数降级和编译测试。
- `domain/`：程序定义、页面定义、运行时协议模型、能力契约、镜像和编译产物。
- `execution/`：虚拟机和发布程序运行时。
- `navigation/`：Studio 导航、定义搜索、引用统计和导航测试。
- `patch/`：图补丁协议、属性补丁、补丁代理和补丁测试。
- `runtime/`：运行时页面、表单、记录对话框、树表支持和标识符生成。
- `storage/`：PostgreSQL 程序存储和生命周期操作。
- `transport/`：浏览器请求封装和 Studio HTTP 接口。
- `ui/`：Studio 工作台的页面、面板、表格、表单和对话框；入口只负责编排。

跨目录引用仍通过 crate 的模块接口完成；目录迁移不改变运行时协议和持久化边界。`compiler`、`patch`、`runtime` 等目录中的片段文件由对应职责模块直接组合，避免在入口文件中继续堆积实现。
