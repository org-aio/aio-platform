# 配对设备的局域网传输

宿主通过 `AIO_LAN_ORIGINS`（最多四个逗号分隔的 HTTPS 来源）公布受信任的局域网入口。入口必须使用浏览器和系统信任的证书、解析到私网并代理到同一个宿主进程；不要把数据库、设备凭据、CDP 或其他管理服务暴露到入口。

`GET /api/runtime/transport` 返回 `data.public_origin` 和 `data.lan_origins`，仅用于无凭据发现与探测。设备将候选按既有配对来源缓存；验证私网地址、TLS 和宿主归属后，通用 worker 请求、Codex WebSocket 与 restic 归档统一优先使用局域网。原配对来源、设备身份和加密用途不变。

浏览器 SDK 的设备视图使用宿主注入的同一清单。探测不带 Cookie；视图仍使用原来按用户、租户、插件版本和挂载限定的短期票据，撤销在每次读取和通道消息时验证。普通账号 API 继续使用登录页面来源。HTTPS 页面到局域网可能需要浏览器的本地网络访问许可；不可达或权限被拒绝时回退公网。

局域网连接失败后设备为该入口冷却 30 秒；后续请求重新选择。失败的业务请求不会自动重放，已建立的通道不会为了周期探测而主动重开。设备断线后仍需遵守原有任务租约和结果确认规则。

原版 Renderer 初始化时可能连续发送大量消息。宿主保留有界网页队列，满时按序等待交付，最长等待 10 秒；网页已关闭或等待超时时，只关闭该视图及其资源等待，不中断同一设备上的其他视图。设备身份、跨挂载隔离和撤权校验仍在原有边界执行。

局域网响应使用管理员声明且匹配请求 Host 的来源构造资源和 WebSocket 地址。不接受任意 Host 或 `X-Forwarded-Host`，CSP 仅增加该视图票据下的资产路径及只读探测路径。
