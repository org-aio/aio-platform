# 一切皆插件：目标与验收

目标是让应用能力、平台服务、执行器、协议入口和演进策略都通过明确的插件契约装配与替换。不能把增加解释器、拆分目录或提供 REST 接口作为整体完成的证明。最小启动器负责装载契约、执行隔离与提交版本；它的升级也需要监督器和可恢复的发布协议。

## 当前可验证进展

- Rhai 和 TypeScript 能编写并执行版本化增强，Wasm 与 sidecar 消费统一授权、租户版本与回滚服务。
- 增强声明输入输出 JSON Schema，由公共执行链离线校验；MCP 工具发现和 gRPC Describe 暴露同一契约。已激活路径的契约在停用或回滚后仍受历史约束，替换语言和执行器不会跳过校验。
- 两种语言通过 `call_enhancement` 组合同包增强，并通过 `call_capability` 调用 Dill 装配的宿主能力；依赖授权、身份快照、计算与等待预算及取消传播由统一调用链约束。候选使用有序调用样例验证，不执行真实副作用。
- 可选 `EvolutionPlugin` 复用版本服务提供脚本演进控制。双语言策略支持候选提交、原子激活、按激活代数观察、回滚和更新策略自身；提交前再次核验会话及权限，拒绝提升调用者能力。Agent 已提供独立 MCP 模型适配器，复用加密配置、Responses 引擎与出站授权；实际产品链路已验证，最终上游模型仍使用 SSE 替身，真实模型质量与生产绑定尚未验收。
- 原生应用插件通过 TypeId 校验重复、缺失依赖和循环；在任何插件构建前完成依赖图检查，并按依赖关系排序。
- `az-plugin-core` 关闭默认 feature 后只保留插件装配及 Dill，不强制引入 HTTP、PostgreSQL 或业务记录实现。
- 宿主的 14 个能力组拥有各自路由；设备、设备视图、剪贴板、个人配置服务由插件注册，运行时及 sidecar 共享同一 Dill 容器。
- MCP Streamable HTTP 与 gRPC unary 由独立插件提供；真实客户端共用增强版本、升级、回滚、权限与撤权检查。可选 `remote` feature 将外部 MCP 工具和 FileDescriptorSet 描述的 unary gRPC 方法导入同一能力层，支持双语言消费、租户绑定、schema 校验、短截止时间、取消和重启恢复。部署文件可在线更新，候选完整校验后原子发布，执行中的脚本固定使用同一能力快照。
- 外部 MCP stdio 复用相同工具与能力契约，部署方声明本机命令及环境变量映射。Linux 真实进程覆盖受限输出、握手、发现、取消、并发配额、停止和进程组回收；进程创建纳入插件任务作用域，整批本地配置通过校验后才启动。它是受信任程序的连接方式，系统沙箱仍由 Sidecar 承担。
- Rhai 与 TypeScript 编译、执行通过 Dill 的执行器契约注入；可移除或替换语言实现。增强服务独立于组件环境，精简 MCP/gRPC 宿主不创建密钥、Wasm、Sidecar 或包缓存。
- `server` 可独立编译和运行协议及外部执行器；`wasm`、`sidecar` 分别加入内置实现。精简宿主和仅 Sidecar 的依赖树不包含 Wasmtime、WASI 或 Cranelift，请求模型不依赖引擎绑定。
- Wasm Component 与 Sidecar 整包执行器通过同一个 `ComponentExecutor` 契约和 Dill 注入；安装、恢复、调用与开发装配使用统一分发。升级或安装事务提交失败会恢复已安装版本。
- v2 整包的 `plugin.required_permissions` 保留宿主角色门槛，安装不会授予这些权限。页面、账户和设置发现、挂载、资源、续期及统一执行器分发实时复核；跨插件调用绑定仍存活的交互上下文，后台和设备不能冒用管理权限。真实 HTTP、PostgreSQL、Wasm 与开发态 Sidecar broker 覆盖撤权、失效、伪造、跨租户、替代执行器、升级回滚及重启索引回填。这是系统包独立交付的权限前提，产品系统包迁移尚未完成。
- 默认包恢复、组件恢复、发布任务恢复与交付后台启动由所选插件声明；可以构建只有自定义服务和路由的组合。
- 数据库、共享密钥、包缓存、进程、Wasm 与组件执行环境由所选插件初始化和关闭；自定义 HTTP 宿主可使用无效数据库配置启动，不读取密钥或创建引擎。数据库连接及密钥来源有可替换 Provider。
- 组件数据库与对象后端由独立 Provider 创建，默认 PostgreSQL 和文件实现可以省略。Wasm、Sidecar 数据库和外部执行器共用租户资源校验；对象命名空间与大小限制保留在运行时，资源关闭包含部分初始化失败及 panic 补偿。
- 身份、发布与实时权限策略、可选计费通过三个独立 Provider 向 Dill 绑定。启动器只接收插件组合，匿名自定义宿主不需要空身份实现；缺失或重复提供者在初始化前拒绝。HTTP、MCP、gRPC、增强和 Sidecar 共享身份实例，业务策略仍保留提交前撤权校验。原生提供者可通过 `RuntimeHost` 在线重建；此项不等于产品系统插件动态交付。
- 宿主生命周期包含部分启动失败补偿、协作取消、后台任务等待、请求关闭和反序资源释放；停止保留安装记录与活动版本，清理错误会汇总返回。
- `aio-idea` 已使用 `RuntimeHost` 在线组合，部署方文件可启停 Rhai、TypeScript、MCP、gRPC、演进控制及字典、文件、权限、租户、市场服务，重建真实身份服务和数据库。系统 Service、Controller 与运行时使用同一个 Dill 容器；每代按依赖初始化，停用关闭连接池并移除路由，重新启用创建新实例并保留数据。身份重启会重建依赖它的系统服务及适配器，会话保持有效。市场服务当前只有无资源的健康路由。系统实现仍编译进宿主，系统 UI 仍静态装配。
- 每代重新装配业务路由与首页快照，应用请求一起排空；初始化、路由返回错误或 panic 都进入补偿和恢复，旧代已关闭资源不能被复用。恢复失败停止监听并交回外部监督器。产品真实 PostgreSQL/HTTP 已验证文件与字典数据保留、旧引用返回 `PoolClosed`、身份依赖重建、MCP 工具目录和正式 gRPC 客户端连续调用，验收入口见 [产品运行时测试](https://github.com/org-aio/aio-idea/blob/9fd090d6bf77dcf72cb285ded5c4fb0d3afaef98/tests/runtime/README.md)。
- 启动配置通过独立于业务插件的 `ConfigurationJournal` 持久化，候选执行前先落盘，运行时就绪后确认；新进程隔离被拒绝或未完成的内容，恢复最后成功组合并保留已停用能力和系统服务。`aio-idea runtime status|retry|restore` 不依赖业务身份、数据库或 `aio.toml`，修改命令与宿主共用操作系统文件锁，锁持有到资源停止完成。记录损坏、来源不符和无成功记录时拒绝启动；持久化失败停止服务。Linux 真实进程已覆盖在线拒绝、零执行器初始化失败、业务初始化等待期间强杀、显式重试与恢复、来源缺失、端口冲突和写盘失败，恢复后五项已停用系统服务的 API 保持 404；macOS/Windows、掉电与生产部署未验收。此机制不更换宿主二进制、不回滚业务数据。

这些进展不代表以下完整验收已经通过。

## 完整目标的验收项

| 要求 | 完成所需证据 | 当前缺口 |
| --- | --- | --- |
| 最小内核只负责契约与机制 | 依赖图证明内核不依赖业务和具体基础设施；启动一个精简宿主 | 最小核心与无数据库 HTTP 宿主已覆盖；Wasm/Sidecar 编译边界已分开；宿主 crate 仍包含数据库、脚本和协议依赖，组件资源后端已可替换，其余宿主服务及基础设施的编译依赖仍需拆分 |
| 平台服务可替换 | 身份、授权策略、数据、对象存储、调度、观测均能替换实现；所有入口消费同一实例 | 已统一四类服务、路由、数据库连接与密钥来源；身份、发布与实时授权、可选计费及组件数据库与对象后端已可替换；数据模型及发布记录仍要求 PostgreSQL，其余服务待迁移 |
| 完整生命周期 | 缺失依赖、循环、部分启动失败、取消、逆序停用与资源释放的故障验收 | 已覆盖启动失败、等待取消、反序关闭、任务清理及协议收尾；RuntimeHost 已实现原生组合在线卸载、按类型重启及依赖重建，覆盖无关单例/任务保留、请求排空、初始化和路由装配失败后的恢复与 MCP/gRPC 连续调用；产品系统服务资源、应用路由及持久启动组合已接入，未协作插件的外部强制终止仍待实现 |
| 执行器也是插件 | Wasm、sidecar、Rhai、TypeScript 通过执行器契约接入；新增执行器不改核心分支 | Rhai/TypeScript 与 Wasm/Sidecar 均可通过执行器契约替换；外部实现覆盖正式发布、HTTP、跨执行器升级与回滚、提交失败和重启恢复。内置 Wasm/Sidecar 已按 feature 分离，v1 分发也使用执行接口；v1 Wasm 产物验证仍绑定可选的内置验证实现 |
| 脚本能组合运行时能力 | 两种语言均可按授权调用其他能力，传播截止时间、取消、幂等与预算；循环被拒绝 | 同包增强已覆盖跨语言组合、完整依赖授权、版本快照、共享预算、循环拒绝和取消传播；宿主能力提供者已接入设备发现、幂等任务提交、查询和取消；Wasm、Sidecar 及协议权限各自衰减。外部 MCP/unary gRPC 的启动导入与部署文件在线更新已覆盖，失败保留旧版、调用链快照和租户隔离有真实协议验收；流式任务和通用副作用协调仍待实现 |
| 协议适配器可插拔 | WIT、HTTP、MCP、gRPC 使用同一能力目录、身份与版本；真实协议客户端验收 | 增强发现与执行已接通 MCP/gRPC；增强及宿主能力发现提供业务输入输出 schema；外部 MCP HTTP/stdio 与 unary gRPC 可导入并在线更新绑定；stdio 已有 Linux 进程验收，macOS/Windows 运行验收、流式 RPC 及 MCP 交互/后台任务待完成 |
| 产品系统能力可动态交付 | 身份、权限、目录及系统 UI 不要求重编宿主；身份插件故障仍可恢复 | aio-idea 的真实身份服务、五项可选系统服务、路由和首页快照已纳入同一运行时生命周期，旧池关闭、数据及会话保留、失败恢复有实测；持久启动记录与独立本机恢复命令已接入。系统实现仍编译进宿主，系统 UI 仍静态装配，停用 API 尚不隐藏菜单；独立交付、契约迁移及 UI 生命周期待实现 |
| AI 自举形成完整闭环 | 能力缺口发现、候选生成、契约验证、授权激活、观测、回退和审计的端到端证据 | 双语言策略、控制插件与 Agent MCP 模型适配器已实现；真实产品/协议覆盖生成接入、验证、提交前撤权、按激活代数观察、回滚、取消和策略自更新。最终上游仍为 SSE 替身，真实模型质量与生产绑定、无人值守调度及失败审计闭环待完成 |
| 原生启动器能够演进 | 独立监督器完成新旧宿主切换、兼容检查、失败恢复与重启验收 | 尚未实现宿主二进制的自更新协议 |

每项验收必须包含真实调用与失败场景。测试必须验证可替换性、停用效果和跨入口的一致性；只检查注册表中出现某个名称或默认配置能启动，不足以证明插件化完成。
