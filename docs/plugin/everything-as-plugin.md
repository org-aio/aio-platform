# 一切皆插件：目标与验收

目标是让应用能力、平台服务、执行器、协议入口和演进策略都通过明确的插件契约装配与替换。不能把增加解释器、拆分目录或提供 REST 接口作为整体完成的证明。最小启动器负责装载契约、执行隔离与提交版本；它的升级也需要监督器和可恢复的发布协议。

## 当前可验证进展

- Rhai 和 TypeScript 能编写并执行版本化增强，Wasm 与 sidecar 消费统一授权、租户版本与回滚服务。
- 两种语言通过 `call_enhancement` 组合同包增强；依赖图、传递授权、版本快照、共享时限与调用预算、取消传播由统一调用链约束。
- 原生应用插件通过 TypeId 校验重复、缺失依赖和循环；在任何插件构建前完成依赖图检查，并按依赖关系排序。
- `az-plugin-core` 关闭默认 feature 后只保留插件装配及 Dill，不强制引入 HTTP、PostgreSQL 或业务记录实现。
- 宿主的 14 个能力组拥有各自路由；设备、设备视图、剪贴板、个人配置服务由插件注册，运行时及 sidecar 共享同一 Dill 容器。
- MCP Streamable HTTP 与 gRPC unary 由独立插件提供；真实客户端共用增强版本、升级、回滚、权限与撤权检查。
- Rhai 与 TypeScript 编译、执行通过 Dill 的执行器契约注入；可移除或替换语言实现。增强服务独立于组件环境，精简 MCP/gRPC 宿主不创建密钥、Wasm、Sidecar 或包缓存。
- Wasm Component 与 Sidecar 整包执行器通过同一个 `ComponentExecutor` 契约和 Dill 注入；安装、恢复、调用与开发装配使用统一分发。升级或安装事务提交失败会恢复已安装版本。
- 默认包恢复、组件恢复、发布任务恢复与交付后台启动由所选插件声明；可以构建只有自定义服务和路由的组合。
- 数据库、共享密钥、包缓存、进程、Wasm 与组件执行环境由所选插件初始化和关闭；自定义 HTTP 宿主可使用无效数据库配置启动，不读取密钥或创建引擎。数据库连接及密钥来源有可替换 Provider。
- 宿主生命周期包含部分启动失败补偿、协作取消、后台任务等待、请求关闭和反序资源释放；停止保留安装记录与活动版本，清理错误会汇总返回。

这些进展不代表以下完整验收已经通过。

## 完整目标的验收项

| 要求 | 完成所需证据 | 当前缺口 |
| --- | --- | --- |
| 最小内核只负责契约与机制 | 依赖图证明内核不依赖业务和具体基础设施；启动一个精简宿主 | 最小核心与无数据库 HTTP 宿主已覆盖；宿主 crate 的编译依赖仍包含各内置基础设施，组件的数据库 provisioner、对象存储与宿主服务仍需拆分 |
| 平台服务可替换 | 身份、授权策略、数据、对象存储、调度、观测均能替换实现；所有入口消费同一实例 | 已统一四类服务、路由、数据库连接与密钥来源；数据模型仍要求 PostgreSQL，其余服务及组件数据库 provisioner、对象存储待迁移 |
| 完整生命周期 | 缺失依赖、循环、部分启动失败、取消、逆序停用与资源释放的故障验收 | 已覆盖启动失败、等待取消、反序关闭、任务清理及协议收尾；原生插件在线卸载、单插件重启、未协作插件的外部强制终止仍待实现 |
| 执行器也是插件 | Wasm、sidecar、Rhai、TypeScript 通过执行器契约接入；新增执行器不改核心分支 | Rhai/TypeScript 与 Wasm/Sidecar 均可通过执行器契约替换；外部实现覆盖正式发布、HTTP、跨执行器升级与回滚、提交失败和重启恢复。旧 v1 包仍使用原有执行路径，内置 Component 引擎的编译依赖尚未按 feature 分离 |
| 脚本能组合运行时能力 | 两种语言均可按授权调用其他能力，传播截止时间、取消、幂等与预算；循环被拒绝 | 同包增强已覆盖跨语言组合、完整依赖授权、版本快照、共享预算、循环拒绝和取消传播；宿主及远端能力提供者、异步副作用与幂等契约仍待实现 |
| 协议适配器可插拔 | WIT、HTTP、MCP、gRPC 使用同一能力目录、身份与版本；真实协议客户端验收 | 增强发现与执行已接通 MCP/gRPC；任意外部服务导入、业务 schema 和流式任务尚未实现 |
| 产品系统能力可动态交付 | 身份、权限、目录及系统 UI 不要求重编宿主；身份插件故障仍可恢复 | aio-idea 仍静态装配系统插件；恢复入口与动态迁移待实现 |
| AI 自举形成完整闭环 | 能力缺口发现、候选生成、契约验证、授权激活、观测、回退和审计的端到端证据 | 候选验证与激活服务存在，尚无模型接入和自动演进策略插件 |
| 原生启动器能够演进 | 独立监督器完成新旧宿主切换、兼容检查、失败恢复与重启验收 | 尚未实现宿主二进制的自更新协议 |

每项验收必须包含真实调用与失败场景。测试必须验证可替换性、停用效果和跨入口的一致性；只检查注册表中出现某个名称或默认配置能启动，不足以证明插件化完成。
