# 一切皆插件：目标与验收

目标是让应用能力、平台服务、执行器、协议入口和演进策略都通过明确的插件契约装配与替换。不能把增加解释器、拆分目录或提供 REST 接口作为整体完成的证明。最小启动器负责装载契约、执行隔离与提交版本；它的升级也需要监督器和可恢复的发布协议。

## 当前可验证进展

- Rhai 和 TypeScript 能编写并执行版本化增强，Wasm 与 sidecar 消费统一授权、租户版本与回滚服务。
- `CapabilityServicePlugin` 独立持有原生与远端能力目录及调用链，`CapabilitiesPlugin` 独立提供 HTTP 目录。原生异步入口与脚本共用显式授权、离线 schema、64 次调用与 1 MiB 传输预算、30 秒截止时间和生命周期取消；出站 MCP/gRPC 无需装配解释器或数据库。
- 增强声明输入输出 JSON Schema，由公共执行链离线校验；MCP 工具发现和 gRPC Describe 暴露同一契约。已激活路径的契约在停用或回滚后仍受历史约束，替换语言和执行器不会跳过校验。
- 两种语言通过 `call_enhancement` 组合同包增强，并通过 `call_capability` 调用 Dill 装配的宿主能力；依赖授权、身份快照、计算与等待预算及取消传播由统一调用链约束。候选使用有序调用样例验证，不执行真实副作用。
- 可选 `EvolutionPlugin` 复用版本服务提供脚本演进控制。双语言策略支持候选提交、原子激活、按激活代数观察、回滚和更新策略自身；提交前再次核验会话及权限，拒绝提升调用者能力。Agent 已提供独立 MCP 模型适配器，复用加密配置、Responses 引擎与出站授权；实际产品链路已验证，最终上游模型仍使用 SSE 替身，真实模型质量与生产绑定尚未验收。
- 原生应用插件通过 TypeId 校验重复、缺失依赖和循环；在任何插件构建前完成依赖图检查，并按依赖关系排序。
- `az-plugin-core` 关闭默认 feature 后只保留插件装配及 Dill，不强制引入 HTTP、PostgreSQL 或业务记录实现。
- 宿主的 14 个能力组拥有各自路由；设备、设备视图、剪贴板、个人配置服务由插件注册，运行时及 sidecar 共享同一 Dill 容器。
- 配对设备通道通过 Dill 聚合 `WebviewProtocolProvider`，Codex/dsh 和内网服务协议由 device 插件声明，宿主不维护固定枚举。会话绑定完整协议和权限契约；缺失、冲突或歧义声明被拒绝。增删 Provider 会重建路由并取消、排空旧连接；真实 HTTP/WebSocket/PostgreSQL 覆盖卸载后的断线与重新安装恢复。内网目标白名单、独立来源网关及目录归 device 插件；目前是本人账号的 HTTP/HTTPS、WebSocket 和 SSE 中继，未提供通用 TCP/UDP 或匿名分享。
- MCP Streamable HTTP 与 gRPC unary 由独立插件提供；原生能力入口只要求能力服务和身份，不要求增强服务、执行器或数据库。MCP 使用 `runtime.*` 名称区分权限域并限制分页大小，gRPC 使用 `aio.runtime.v1.Capabilities`；原生结果不伪造脚本 revision。真实客户端共用增强版本、升级、回滚、权限与撤权检查。可选 `remote` feature 将外部 MCP 工具和 FileDescriptorSet 描述的 unary gRPC 方法导入同一能力层，支持双语言消费、租户绑定、schema 校验、短截止时间、取消和重启恢复。部署文件可在线更新，候选完整校验后原子发布，执行中的脚本固定使用同一能力快照。
- 外部 MCP stdio 复用相同工具与能力契约，部署方声明本机命令及环境变量映射。Linux 真实进程覆盖受限输出、握手、发现、取消、并发配额、停止和进程组回收；进程创建纳入插件任务作用域，整批本地配置通过校验后才启动。它是受信任程序的连接方式，系统沙箱仍由 Sidecar 承担。
- 产品同时关闭 Rhai/TypeScript 时自动移除脚本、增强及演进服务，MCP/gRPC 原生能力保留。重新启用语言不改变持久增强摘要和激活代数；只恢复不匹配语言或缺少混合包任一语言时，整包暂停发现与执行，原生目录不受影响。缺失 gRPC 服务返回协议级 Unimplemented；数据库、摘要和编译错误仍暴露。演进控制保留部署开关，不会擅自重新启用。
- Rhai 与 TypeScript 编译、执行通过 Dill 的执行器契约注入；可移除或替换语言实现。增强服务独立于组件环境，精简 MCP/gRPC 宿主不创建密钥、Wasm、Sidecar 或包缓存。
- `server` 编译宿主契约及平台服务，`rhai`、`typescript`、`mcp`、`grpc`、`remote-mcp`、`remote-grpc`、`wasm`、`sidecar` 分别选择具体实现；`remote` 聚合两种出站协议。生产依赖检查覆盖 12 种宿主组合和 4 种独立运行时组合，精简宿主不带入内置语言或协议，纯 Sidecar 不引入 Wasmtime、WASI 或 Cranelift。协议宿主可完全省略脚本服务，也可装配外部脚本执行器，完整应用显式选择双语言和两种入站协议。
- v1 Wasm 的产物校验也由所选 `WasmExecutor` 提供，通过中立的 `WasmArtifactValidator` 接入 Git 安装、已发布包与开发快照。公共层仍统一验证页面模型、声明和前端文件；执行器缺失、重复或校验失败不会回退到内置 Wasmtime。在线替换会重建仓库服务。有限替身覆盖真实 HTTP/PostgreSQL 发布、调用、缺失暂停、恢复和坏候选拒绝；真实生成组件通过当前提交的宿主验证校验结果、激活页面及租户隔离，不再使用固定旧版应用的测试。
- Wasm Component 与 Sidecar 整包执行器通过同一个 `ComponentExecutor` 契约和 Dill 注入；安装、恢复、调用与开发装配使用统一分发。升级或安装事务提交失败会恢复已安装版本。
- 执行器缺失时，已安装 v1/v2 插件保留启用意图与版本，目录显示 `suspended`，页面、账户、设置及组件权限随实际运行绑定暂停。组件管理面允许零执行器，可停用、卸载或显式迁移到可用执行器；提交失败保留原暂停状态。恢复不改变摘要、代数及回滚排除记录，损坏整包和歧义匹配仍报错。自动升级保留暂停实例的任务，同时继续处理可运行租户。替代执行器真实 HTTP/PostgreSQL、旧版持久记录、Wasm 与 Sidecar 资源及升级队列均有回归覆盖。
- v2 整包的 `plugin.required_permissions` 保留宿主角色门槛，安装不会授予这些权限。页面、账户和设置发现、挂载、资源、续期及统一执行器分发实时复核；跨插件调用绑定仍存活的交互上下文，后台和设备不能冒用管理权限。真实 HTTP、PostgreSQL、Wasm 与开发态 Sidecar broker 覆盖撤权、失效、伪造、跨租户、替代执行器、升级回滚及重启索引回填。字典和市场已使用此契约独立交付，其他产品系统包仍待迁移。
- 默认包恢复、组件恢复、发布任务恢复与交付后台启动由所选插件声明；可以构建只有自定义服务和路由的组合。
- 可选 `ComponentBootstrapPlugin` 从部署方固定摘要的本地 v2 整包为明确租户执行首次安装，无需市场界面；整批输入先校验，父包先安装，缺执行器暂缓并随装配恢复。首次安装意图与安装同事务持久化，重启不重置升级、回滚、停用或卸载选择，也不覆盖已有最新发布；部分失败只续装未提交项。管理包另需部署方按整包摘要信任，身份高权限包仍拒绝；字典和市场已使用该入口动态交付，其他系统 UI 仍待迁移，细节见 [整包首次引导](component-bootstrap.md)。
- 可选 `ComponentManagementPlugin` 按来源及整包摘要授予系统包公共管理能力，Wasm、Sidecar 和挂载前端复用真实交互与实时权限检查，拒绝后台、伪造及跨插件转授。前端可升级、回滚、停用和卸载自身；执行器内同步生命周期变更拒绝以避免排空死锁。撤信任暂停安装并保留版本/代数，重新信任按原记录恢复；产品部署组合在线持久化此声明。真实 HTTP/PostgreSQL、Wasm、Unix broker 与 Chromium 桥接覆盖相关边界，Sidecar 监督器仍是测试夹具。管理前端已提供受手势约束的设置和本机助手操作，以及经过同一授权的大包原始下载通道；超过 32 MiB 的真实整包和浏览器动作取消已验证。市场 UI 与设备工作流已迁至独立整包；管理写入等待对应目录提交，避免自升级后的旧页面续发请求。见 [系统整包管理](component-management.md)。
- 配对、设备网页、个人配置和剪贴板的默认服务各自拥有业务表迁移，不再依赖 `StorePlugin`。纯配对与设备网页宿主无需创建旧版插件目录、市场或交付表；默认实现保留设备表关联，替代存储需替换相关默认服务。真实 PostgreSQL 覆盖按需建表、加密读写、重启恢复和事务失败回滚。
- 数据库、共享密钥、包缓存、进程、Wasm 与组件执行环境由所选插件初始化和关闭；自定义 HTTP 宿主可使用无效数据库配置启动，不读取密钥或创建引擎。数据库连接及密钥来源有可替换 Provider。
- 组件环境可完全省略增强服务，照常安装、恢复和执行组件；缺失服务时拒绝增强调用。可选服务通过同一 Dill 容器解析，参与初始化排序与在线依赖重建，重复绑定和构造失败仍返回错误。
- 组件数据库与对象后端由独立 Provider 创建，默认 PostgreSQL 和文件实现可以省略。Wasm、Sidecar 数据库和外部执行器共用租户资源校验；对象命名空间与大小限制保留在运行时，资源关闭包含部分初始化失败及 panic 补偿。
- 执行运行时的租户数据库、事务值模型和发布记录已改为中立契约：`DatabaseBackend`、`DatabaseTransaction`、`ComponentReleases` 与版本读租约。`wasm` 不引入 SQLx/SQL parser，`postgres` 不引入 Wasmtime；默认 PostgreSQL 实现沿用角色隔离、受控迁移、原发布表及审计。运行时统一执行配额、取消、失败回滚及来源/租户校验；Sidecar 消费后端声明的专属连接及 TCP/Unix 代理信息。真实 SQLite 测试替代数据和发布存储，覆盖 WIT 读写、独立连接的并发激活、取消排空、重启恢复及提交失败，生产默认仍为 PostgreSQL。宿主默认安装与发布目录仍使用 PostgreSQL，编译由独立 `postgres` feature 控制。
- 身份、发布与实时权限策略、可选计费通过三个独立 Provider 向 Dill 绑定。启动器只接收插件组合，匿名自定义宿主不需要空身份实现；缺失或重复提供者在初始化前拒绝。HTTP、MCP、gRPC、增强和 Sidecar 共享身份实例，业务策略仍保留提交前撤权校验。原生提供者可通过 `RuntimeHost` 在线重建；此项不等于产品系统插件动态交付。
- 宿主生命周期包含部分启动失败补偿、协作取消、后台任务等待、请求关闭和反序资源释放；停止保留安装记录与活动版本，清理错误会汇总返回。
- `aio-idea` 已使用 `RuntimeHost` 在线组合，部署方文件可启停 Rhai、TypeScript、Wasm、Sidecar、MCP、gRPC、演进控制及文件、权限、租户服务，重建真实身份服务和数据库。系统 Service、Controller 与运行时使用同一个 Dill 容器；每代按依赖初始化，停用关闭连接池并移除路由，重新启用创建新实例并保留数据。身份重启会重建依赖它的系统服务及适配器，会话保持有效。字典和市场已移除宿主编译依赖；其余系统实现和 UI 仍静态装配。
- 每代重新装配业务路由与首页快照，应用请求一起排空；初始化、路由返回错误或 panic 都进入补偿和恢复，旧代已关闭资源不能被复用。恢复失败停止监听并交回外部监督器。产品真实 PostgreSQL/HTTP 已验证文件数据保留、旧引用返回 `PoolClosed`、身份依赖重建、MCP 工具目录和正式 gRPC 客户端连续调用，验收入口见 [产品运行时测试](https://github.com/org-aio/aio-idea/blob/main/tests/runtime/README.md)。
- Sidecar 调用现在带回会话权限：`RequestContext` 增加带默认值的 `permissions`，宿主在唯一的请求登记点写入，交互与跨插件派生调用共用同一份集合，授权校验与插件读到的内容完全一致。Sidecar SDK 的 `Caller` 暴露 `permissions` 与 `has_permission`，空项、重复项、超长与控制字符一律 401；设备 worker 通道不携带用户会话权限。Wasm 组件继续使用既有 `authorize(permission)` 查询通道，不改 WIT 记录。这是让权限、租户等系统服务脱离静态编译的前置能力；它们仍缺一个受控的宿主身份服务通道（创建用户、重置密码、切换会话），因此尚未迁出静态组合。

- 宿主二进制的自我演进由独立 `az-plugin-launcher` 承担，它是信任根且不依赖宿主代码：`boot` 在 systemd 服务内校验 `release-manifest.json` 后 exec 成宿主，PID、stdout 与生命周期不中断；`activate` 由部署侧完成候选摘要校验、`current` 原子切换、服务重启与健康确认，失败回滚并在 `switch.json` 记录原因；`repair` 处理崩溃事务，`adopt` 为协议迁移前的旧发布补写清单。切换事务用持有者 PID 与进程起始时间区分在途与崩溃，服务内调用 `activate` 会被拒绝。真实产品二进制已覆盖上述路径；实际生产初装与跨版本上线仍待验收。见 [固定发布启动器](../../lib/plugin/launcher/README.md)。

- 启动配置通过独立于业务插件的 `ConfigurationJournal` 持久化，候选执行前先落盘，运行时就绪后确认；新进程隔离被拒绝或未完成的内容，恢复最后成功组合并保留已停用能力和系统服务。`aio-idea runtime status|retry|restore|migrate` 不依赖业务身份、数据库或 `aio.toml`，修改命令与宿主共用操作系统文件锁，锁持有到资源停止完成。记录损坏、来源不符和无成功记录时拒绝启动；持久化失败停止服务。Linux 真实进程已覆盖零语言首次启动、增强停用后强杀与单语言恢复、在线拒绝、文件资源初始化失败、业务初始化等待期间强杀、显式重试与恢复、来源缺失、端口冲突和写盘失败，恢复后三项已停用系统服务的 API 保持 404；macOS/Windows、掉电与生产部署未验收。`migrate` 校验并移除退役的原生字典及市场配置；迁移与恢复只暂存候选，实际启动成功前保留最后成功记录。此机制不更换宿主二进制、不回滚业务数据。

- `az-plugin-process` 原生进程 SDK 提供有界宿主配置、可信入口和终止信号排空，业务复用一个 Dill 容器。字典已拆出宿主编译依赖，以独立 v2 Sidecar 包携带既有 Controller/Service、Dioxus UI 和 SQL 迁移；旧数据按权威租户绑定复制，重复执行可核对，冲突整批回滚，旧表保留。真实产品、Docker、PostgreSQL 和桌面/手机浏览器覆盖安装、升级、回滚、菜单隐藏、跨重启停用、实时撤权及数据保留，宿主二进制摘要不变，入口见 [字典整包验收](https://github.com/org-aio/aio-plugin-dictionary/blob/5b8cf7b12ce8c25f69dc8c6559c7d73a7551d5b7/tests/README.md)。
- 市场已从 `aio-idea` 的静态前后端依赖、账户入口和原生服务组合中移出，以 v2 Wasm 整包动态贡献工作区及账户页面。真实产品、PostgreSQL 和 Chromium 覆盖固定摘要首次引导、安装/指定版本/升级/回滚、自升级/自停用、跨重启停用及显式恢复，宿主二进制摘要不变。另覆盖文档图片、逐字节下载、设置、分享/刷新/前后退/滚动及桌面/手机布局；CLI 的正式任务链使用模拟设备回报，本机助手只验收协议动作，未执行实际软件安装。见[市场整包验收](https://github.com/org-aio/aio-plugin-marketplace/blob/main/tests/README.md)。
- Sidecar 停止先排空再等待容器清理，重启前只清理确认无存活容器的旧 Unix socket；普通文件和符号链接被拒绝。重新启用恢复已选摘要并保留回滚排除记录，不能隐式升级；真实权限、前端版本和数据库记录共同验收。

- v2 整包目录通过 `ComponentCatalog` 独立装配，发布、安装、回滚、停用、首次引导、权限索引、Sidecar 密钥与用户记录、升级选择不再直接访问 PostgreSQL。默认实现保留正式表与交付同事务语义，安装提交检查代数。文件持久化夹具验证完全不连接 PostgreSQL 的最小自举/重启/卸载，以及不创建整包表的真实 HTTP 生命周期和失败补偿；默认实现另有跨连接并发验收。默认设备业务表和交付存储仍采用 PostgreSQL，host 的中立组合不编译该实现，文件夹具不是生产提供者。见 [目录契约](../../lib/plugin/host/src/runtime/server/component_catalog/README.md)。

- v1 目录已通过 `PluginCatalog` 统一注入，公共管理、前端、安装恢复和发布任务不再取得具体目录连接池；包、安装、页面状态、发布顺序及导航偏好由同一提供者保证一致性。文件持久化夹具以无效数据库配置验证真实 HTTP 生命周期、重启恢复、撤权及提交失败后的执行器补偿。默认 PostgreSQL 交付和 CLI 工具仍明确依赖 `StorePlugin`；交付协议与文档入口已可独立替换，默认跨业务表查询仍需进一步拆分；它们仅由 `postgres` feature 编译。见 [旧版目录契约](../../lib/plugin/host/src/runtime/server/plugin_catalog/README.md)。

- 交付协议通过 `DeliveryService` 装配，文档通过 `PluginDocumentation` 装配；`DeliveryPlugin` 和 `DocumentationPlugin` 不再直接取得数据库。默认 PostgreSQL 协调器与文档实现各自拥有独立插件；发现、发布推进和滚动升级由独立插件按生命周期启动和排空。无数据库文件夹具覆盖真实 HTTP 构建领取、页面发布安装、重启恢复、文档图片、管理权限、提交失败和在线替换；默认实现保留跨表事务，v1 发布任务与构建完成状态现在原子提交，过期租约不能复活任务。GitHub 发现器消费中立 `DeliverySources` 契约，来源代数、撤销墓碑、任务入队及旧租约取消原子提交；可独立移除发现器或替换存储，已有构建仍能完成。默认自动升级独立于发布推进，停用自动升级仍可发布新包。真实 HTTP 替身、文件存储和 PostgreSQL 覆盖陈旧响应、故障回滚、重启与在线替换；队列租约、退避和默认时钟仍属各默认实现内部策略。见 [交付装配](../../lib/plugin/host/src/runtime/server/delivery/README.md)。

- 增强版本持久化通过 `EnhancementCatalog` 独立装配，默认 PostgreSQL 提供者负责表初始化与原子提交。公共增强服务、双语言、演进策略和协议不再直接取得连接池；锁后授权复核、CAS、回滚资格、历史 schema 与审计保留事务语义。文件夹具覆盖无数据库配置的真实 HTTP/MCP/gRPC、在线提供者替换、重启、提交失败及停用恢复；共同事务验收使用文件提供者与独立 PostgreSQL 连接。正式默认仍为 PostgreSQL，宿主默认业务的 SQLx 实现由独立 `postgres` feature 选择。见[增强存储契约](../../lib/plugin/host/src/runtime/server/enhancement_catalog/README.md)。

- 宿主 PostgreSQL 实现由显式 `postgres` feature 编译，`server`、Rhai、TypeScript、Wasm、Sidecar 与 MCP/gRPC 入站/出站组合不引入 SQLx 或 SQL parser。公共模型、包恢复与 GitHub 发现器保留在中立边界；设备长轮询、Skill 授权与归档密钥改用服务契约。文件夹具直接运行 v1/v2 真实 HTTP 安装、升级、回滚和重启；默认提供者保留事务与可重试故障语义。正式产品与开发宿主仍显式选择 PostgreSQL，不把文件夹具当生产存储。

- Sidecar 已通过启动时固定授权的 Unix broker 复用运行时对象存储，原生 SDK 不依赖宿主实现或数据库。二进制接口保留来源/租户隔离、单对象 16 MiB 限额、并发与总截止时间；上传、排队、下载结束及实例停止均复核或撤销授权。真实 broker、SDK、PostgreSQL 安装目录与文件后端覆盖隔离、故障注入、超限、升级撤权、重启和取消。文件插件已作为 v2 Sidecar 整包独立交付：分块上传、100 MiB 上限、匿名图片路由、旧数据迁移工具和独立前端均已实现，产品不再注册原生 `/api/files` 或站点根图床；真实宿主、Docker、PostgreSQL 与桌面/手机浏览器完成安装、升级、回滚、停用、撤权、清理和卸载验收。见 [Sidecar 对象存储](process-storage.md)。

- 插件资源通过统一流式执行器契约读取：有身份下载沿用挂载、实时权限及交互上下文，匿名资源必须在整包中声明路径、类型和大小，Sidecar SDK 只注入绑定租户。流式任务纳入插件生命周期，限制字节、截止时间和并发，慢速下游也能取消并释放资源；真实 HTTP、Unix SDK 和 opaque iframe 验证 100 MiB 下载及撤权。文件插件的分块持久化、旧数据迁移、独立前端和产品静态依赖移除已完成；真实浏览器验证逐块上传取消、下载字节、公开图片、撤权、清理和卸载。见 [插件资源流](component-resources.md)。

这些进展不代表以下完整验收已经通过。
