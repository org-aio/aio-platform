# Sidecar 对象存储

v2 进程整包可在清单中声明 `[plugin.capabilities] storage = true`。启动配置中的 `storage: true` 表示当前进程持有此能力；无授权时省略该字段。业务可使用 `az-plugin-process` 的 `host.storage()?`，也可直接通过配置中的 `broker_socket` 调用 HTTP 协议。此接口不要求宿主编译 PostgreSQL。

运行时在创建进程时从已验证整包生成 `ObjectStore`，固定插件来源、租户和授权快照。所有读写复用与 Wasm 相同的对象后端、键摘要和命名空间。旧进程不能获得新版本新增的存储授权；更换存储提供者也不改变 SDK 或协议。

| 请求 | 请求体 | 成功响应 |
| --- | --- | --- |
| `GET /storage?key=<URL 编码键>` | 无 | `200 application/octet-stream`；对象不存在为 `404` |
| `PUT /storage?key=<URL 编码键>` | 原始二进制 | `204`，覆盖同键对象 |
| `DELETE /storage?key=<URL 编码键>` | 无 | `204`，对象不存在也成功 |

每个请求须带唯一的 `x-aio-token`，值来自当前启动配置。键必须为 1–1024 个 UTF-8 字节；额外 query 参数不被接受。租户、来源、文件系统路径不能由请求选择。响应不会包含后端错误细节，读取响应禁止缓存。该授权属于插件服务身份；业务路由仍须通过 `Host::protect` 和宿主会话、权限校验，不可把 broker 暴露给浏览器。

每个对象的读写上限为 16 MiB，可写入空对象。broker 先校验凭据和能力再读请求体，共享进程的 8 个并发名额，读取请求体、排队和后端访问合计最多 30 秒。下载以 64 KiB 帧传输，在响应结束前持有并发额度，后续帧继续检查截止时间和实例停止信号。超额并发返回 `429`、超大上传返回 `413`、总预算耗尽返回 `408`，参数无效返回 `400`，撤权返回 `403`，后端故障返回 `502`。SDK 对下载同样执行长度限制，对非 `404` 失败返回错误，不把故障伪装成对象不存在。

宿主在开始、读完上传及取得存储操作锁后复核活动版本；下载完成后再次复核再返回内容。实例停止会取消存储请求，包括已经建立连接的请求。后端实现须支持 Future 被取消时释放临时资源，默认文件后端使用自动回收的临时文件和原子重命名。取消不是数据库事务回滚：已提交写入在超时或断连后仍可能存在，调用者应使用稳定键读取核对后重试；数据库元数据与对象之间的补偿由业务负责。

这不是文件管理插件的迁移声明。已有文件管理支持更大文件与匿名图片链接，后续迁移还须实现分块、旧对象迁移和明确的匿名路由契约，不能直接降低上传上限或绕开管理权限。

验收使用真实 Unix broker、SDK、PostgreSQL 安装目录与文件后端；进程包中的 ELF 仅用于配置校验，不在本测试中启动业务 Sidecar：

```sh
cargo test -p az-plugin-host --no-default-features --features postgres,sidecar \
  --lib sidecar_storage_ -- --ignored --test-threads=1
```

测试库通过 `AIO_COMPONENT_TEST_DATABASE_URL` 指定，必须为 `127.0.0.1` 上名称以 `_test` 结尾的独立数据库，并撤销 PUBLIC 的 schema 权限。覆盖 16 MiB 往返、跨租户与跨来源隔离、缺失授权、伪造票据、旧版本、上传中撤权、等待锁后撤权、实例停止、重启持久化、幂等删除、慢请求超时、慢上传/下载的并发耗尽和可替换后端故障。
